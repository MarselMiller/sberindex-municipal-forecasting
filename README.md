# СберИндекс: прогнозирование расходов и сигналы изменений

**Версия 0.1 — исполняемый первый этап проекта, а не законченная конкурсная работа.**

В комплект входят предоставленные пользователем данные, Python-код, конфигурации,
автоматические тесты, учебный ноутбук и результаты действительно выполненного backtest.
Прогнозируется месячное значение категории **«Все категории»** на уровне МО в исходных рублях.
Это оценка средних безналичных расходов, а не общий оборот муниципалитета.

## Начать без запуска

Откройте `outputs/baseline_v1/experiment_report.md` — это отчёт с фактическими результатами.
Таблица с числами: `outputs/baseline_v1/metrics.csv`.
Пошаговый разбор кода: `notebooks/01_start_here.ipynb`.
Сохранённый ноутбук можно прочитать, даже не выполняя расчёт заново.

## Установка и запуск — Windows PowerShell

Сначала распакуйте ZIP, откройте терминал **в папке с `run.py`**.
Скрипты обращаются к данным относительно проекта, а не диска автора.
Для наиболее близкого воспроизведения используйте Python 3.13; исходный запуск выполнен
на Python 3.13.5/Linux. Windows здесь отдельно не проверялся.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe run.py all --config configs/local_run.yaml
```

Активация окружения не нужна: используется прямой путь к Python, поэтому изменение
ExecutionPolicy PowerShell не требуется. Если `py -3.13` не найден, сначала установите
Python 3.13 с официального сайта Python. Файлы данных дополнительно скачивать не нужно.

Результаты вашего запуска появятся в `outputs/baseline_local/`;
исходные результаты `outputs/baseline_v1/` останутся как эталон сравнения.
Для повторного полного обучения добавьте `--rerun`. Без этого ключа уже рассчитанные
разделы с совпадающими данными и конфигурацией будут прочитаны с диска.

## Linux / macOS

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest
.venv/bin/python run.py all --config configs/local_run.yaml
```

`requirements.txt` фиксирует основные версии проверенного запуска.
`requirements-lock.txt` дополнительно фиксирует установленные транзитивные зависимости
этого окружения; это не универсальный системный образ для всех ОС.

Можно считать по частям:

```bash
python run.py backtest --config configs/local_run.yaml --origins 2023-12 2024-01
```

Для окончательной сводки необходимо рассчитать все 12 заданных точек выпуска.
Неполный прогон явно помечается; сигналы детекторов на нём не рассчитываются.
При изменении признаков, данных или параметров задайте **новый `output_dir`** в YAML,
чтобы не смешать результаты разных экспериментов. Старую конфигурацию не перезаписывайте.

## Как устроен эксперимент

Точки выпуска: конец каждого месяца с декабря 2023 по ноябрь 2024.
Горизонт — 1, 3, 6 или 12 **календарных месяцев от даты выпуска**, а не сумма за период.
На каждой точке модель видит только условно доступную историю и переобучается заново.

Сначала проверяются цели до июня 2024 включительно (валидация).
Отдельно показаны ошибки заранее зафиксированных моделей на целях июля–декабря 2024.

**Дата выбора алгоритма тоже имеет значение.** Выбор по результатам до июня известен
не раньше конца июня. Его нельзя применить задним числом к шестимесячному прогнозу,
выпущенному в январе. Поэтому итоговая стратегия выбора оценивается отдельно в
`selected_policy_metrics.csv`, только на прогнозах, выпущенных после выбора.
Для h=6 там остаётся одна точка выпуска, для h=3 — четыре, для h=1 — шесть.
Для h=12 нет валидации: SeasonalNaive назначен заранее, а проверочная дата всего одна.

**Существенное допущение:** в исходных файлах нет проверенных дат публикации и vintages.
В первом эксперименте значение месяца считается доступным в его последний день
(`release_lag_months: 0`). Это ретроспективная симуляция, а не доказанное воспроизведение
исторически доступной информации. Изменение лага доступно через YAML; точные timestamps
и пересмотры потребуют отдельного расширения данных. Индекс `ds` обозначает месяц,
а не фактическую дату публикации показателя.

## Метрики и результаты

Основная метрика — **MAE в исходных рублях**:
`mean(abs(y_true - y_pred))`.

`mae_macro`: сначала MAE каждого МО, затем среднее по МО с одинаковыми весами.
`mae_micro`: среднее по всем прогнозным парам; при разном покрытии веса МО различаются.
`r2_pooled`: R² по общему пулу наблюдений. Из-за различий уровней между МО он не заменяет
проверку временной динамики; R² по отдельным МО сохранён отдельно. Для постоянного
или одноточечного ряда R² не определён и записывается как NaN.

Общее сравнение всегда использует одинаковую область доступных фактов и прогнозов.
`coverage.csv` и `partitions/cohort_*.csv` показывают исключения, отсутствующие факты,
покрытие и резервные прогнозы. Отсутствующие целевые месяцы не заменяются нулями.

Нельзя объявлять SeasonalNaiveYoY окончательным победителем конкурса: Prophet ещё не
проверен, долгосрочная оценка ограничена длиной данных, внешние признаки пока отсутствуют.
Объединённая стратегия выбора на h=6 оказалась нестабильной — это отражено в отчёте,
а не исправлено задним числом по тестовой ошибке.

## Prophet — следующий отдельный запуск

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-prophet.txt
.\.venv\Scripts\python.exe run.py all --config configs/prophet_comparison.yaml
```

Здесь сравниваются все шесть алгоритмов на общей фиксированной выборке **до 64 МО**,
случайно выбранной с seed=42 из допустимых на первой дате, без просмотра будущего.
Это отдельный пилот, его MAE нельзя напрямую сравнивать с MAE полного набора в baseline_v1.
Установите `max_series: null` и новый `output_dir` для полного сравнения.

ProphetAuto использует автоматическую годовую сезонность.
ProphetYearly использует заранее заданный порядок Fourier=3.
Оба прогнозируют только месячные даты; дневная и недельная сезонность отключены.
Это не настройка Prophet на валидации и не точная модель организаторов:
её код пока не предоставлен. Если Prophet не установлен, запуск явно останавливается,
а не заменяет его другим методом под тем же названием.

## Данные и публикация

Это приватный рабочий пакет для владельца исходных загрузок, не опубликованный датасет.
