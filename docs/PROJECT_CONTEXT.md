# Паспорт проекта

Дата исходного описания: 2026-10-05.
Основа: предоставленные пользователем условия, архив sberindex_python_mvp.zip,
README и сохранённый отчёт outputs/baseline_v1/experiment_report.md.
Этот документ — передача контекста, не новый расчёт и не подтверждение запуска на компьютере пользователя.

## Цель
Прогнозирование потребительских расходов на уровне муниципальных образований (МО)
и раннее обнаружение/предупреждение структурных изменений.
Прогнозные горизонты: 1, 3, 6, 12 календарных месяцев.
Основная метрика: MAE в исходных рублях; R² — дополнительная.
Нужно сравнение с Prophet и, при наличии, отдельной базовой моделью организаторов.

## Критерии конкурса
Понятное объяснение — 10%; сравнение прогнозов — 20%; сравнение детекторов — 20%;
фундаментальная модель — 15%; новости и корректное согласование — 15%;
метрики с обязательной MAE — 10%; интерпретация и воспроизводимость — 10%.

## Данные и ограничения
По сохранённому аудиту: месячная история 2023-01—2024-12, 2 190 территорий;
50 521 наблюдение по целевой категории «Все категории».
Вход текущего MVP: data/input/consumption_all_categories.csv.
Не суммировать «Все категории» с остальными категориями.
Цель описывается как оценка средних безналичных расходов жителей, а не весь оборот МО;
перед финальным отчётом сверить точное определение с документацией источника.
Идентификаторы территорий имеют исторические версии; присоединение должно учитывать время.
Даты публикации и исторические версии расходов не подтверждены.
release_lag_months: 0 — допущение первого эксперимента, а не установленный факт.
Для h=12 в имеющемся первом эксперименте всего одна дата выпуска и проверки.
Это не позволяет делать устойчивый рейтинг годовых прогнозов.

## Что находится в исходном MVP
Код загрузки, признаков, временного backtest, MAE/R² и диагностических сигналов.
Сохранены результаты LastValue, SeasonalNaive, SeasonalNaiveYoY, CatBoostRecursive.
Сохранённые результаты — не то же самое, что воспроизведение у пользователя.
ProphetAuto/ProphetYearly: адаптеры и configs/prophet_comparison.yaml;
в исходной версии результаты их запуска отсутствуют.
CUSUM/EWMA: диагностические сигналы, не оценённая система предсказания будущих шоков.
Фундаментальная модель, новости, независимая оценка шоков и финальная защита не завершены.

## Среда и запуск
README исходного пакета указывает Python 3.13.5/Linux как среду прежнего запуска.
Версии основных зависимостей находятся в requirements.txt.
ОС, доступный Python, Git, оперативная память и точное VS Code-расширение пользователя
ещё нужно проверить, а не предполагать.
Локальная конфигурация: configs/local_run.yaml → outputs/baseline_local.
Prophet-пилот: configs/prophet_comparison.yaml → отдельный каталог результатов,
общая выборка до 64 МО. Пилот нельзя напрямую сравнивать с полным набором других запусков.

## Организация работы
Основная рабочая копия находится у пользователя и версионируется через Git.
Браузерный чат: постановка эксперимента, методология, интерпретация, проверка выводов.
Расширение VS Code, если поддерживает работу с файлами: реализация ограниченной задачи,
проверка diff и разрешённые запуски в локальной среде.
Не рассчитывать на автоматическую передачу истории чата: передавать эти документы и текущую задачу.
Одна задача → согласованные изменения → проверка → результаты → обсуждение → commit.
README объясняет запуск; этот файл хранит текущую постановку и устойчивые решения;
docs/TASKS.md хранит план и критерии завершения.

## Честность оценки
Результаты baseline_v1 уже просмотрены и обсуждались. Не называть дальнейшую
итеративную настройку по тем же датам независимой слепой проверкой.
До расширения экспериментов зафиксировать доступный протокол выбора и проверки,
явно различать исследовательские сравнения и действительно неиспользованную проверку.
Нельзя создавать видимость независимости простым переименованием старого теста.

## Финальные артефакты
GitHub-репозиторий: код, README, конфигурации, тесты, воспроизводимый путь подготовки данных.
Русский методологический отчёт с источниками, метриками и ограничениями.
Презентация PDF или лендинг: архитектура, сравнения, новости, реальные примеры.
Таблицы и графики должны иметь связь с конкретными запусками, конфигурациями и кодом.
Данные и секреты не публиковать до отдельной проверки состава и условий.
Текущий .gitignore исключает data/input/* и outputs/*: для финальных разрешённых
сводок потребуется отдельное место, например reports/results/ и reports/figures/.
