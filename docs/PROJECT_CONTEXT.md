Дата исходного описания: 2026-10-05.
Основа: предоставленные пользователем условия, архив sberindex_python_mvp.zip,
README и сохранённый отчёт outputs/baseline_v1/experiment_report.md.

E04a, аудита E05a, E05b, E05c и E05d на 2026-10-07. Источник каждого нового вывода указан ниже.

## Цель
Прогнозирование потребительских расходов на уровне муниципальных образований (МО)
и раннее обнаружение/предупреждение структурных изменений.
Прогнозные горизонты: 1, 3, 6, 12 календарных месяцев.
Основная метрика: MAE в исходных рублях; R² — дополнительная.
Нужно сравнение с Prophet и, при наличии, отдельной базовой моделью организаторов.

## Критерии конкурса
Понятное объяснение — 10%; сравнение прогнозов — 20%; сравнение детекторов — 20%;
фундаментальная модель — 15%; новости и корректное согласование — 15%;
метрики с обязательной MAE — 10%; интерпретация и воспроизводимость — 10%.

## Данные и ограничения
По сохранённому аудиту: месячная история 2023-01—2024-12, 2 190 территорий;
50 521 наблюдение по целевой категории «Все категории».
Вход текущего MVP: data/input/consumption_all_categories.csv.
Не суммировать «Все категории» с остальными категориями.
Цель описывается как оценка средних безналичных расходов жителей, а не весь оборот МО;
перед финальным отчётом сверить точное определение с документацией источника.
Идентификаторы территорий имеют исторические версии; присоединение должно учитывать время.
Даты публикации и исторические версии расходов не подтверждены.
release_lag_months: 0 — допущение первого эксперимента, а не установленный факт.
Для h=12 в имеющемся первом эксперименте всего одна дата выпуска и проверки.
Это не позволяет делать устойчивый рейтинг годовых прогнозов.

## E05d: фиксированное National/Local и LightGBM
Конфигурация configs/national_local_lightgbm.yaml; скрипт
scripts/run_national_local_lightgbm.py; результаты outputs/national_local_lightgbm_v1/;
отчёт reports/results/E05d_national_local_lightgbm.md. Отдельные модули

N_t — медиана всех конечных фактов текущего месяца всей панели 2190 МО,
а не только пилота и не заранее отобранной по будущей полноте когорты.
Причинный знаменатель missing_share — МО с хотя бы одним конечным фактом
до данного месяца включительно. Сохранены used/known/missing, медиана,
min/p10/q25/q75/p90/max. В 24 месяцах used=2072…2149, known=2143…2190,
N=20632…32172 рублей; некорректных N нет, все 50521 конечное наблюдение
сохранились в R=y/N. Меняющийся состав МО может влиять на медиану.
N — производная характеристика наблюдаемой панели, не внешняя инфляция
и не совокупный оборот МО.

Для O национальная история ограничена O−L. Прозрачный адаптер вызывает
неизменный baseline_predict SeasonalNaiveYoY на шаге h+L: сезонное значение
× медиана YoY из трёх последних календарных позиций, границы [0.5,2],
прежние правила NaN/резерва. Actual future N доступен только диагностике.
R допускается при конечном N>0; иначе NaN с явной причиной, без констант.
Исторические признаки используют информацию до r−L; цель и N_(r+h)
допускаются только при r+h+L≤O. Для каждой метки сохранены denominator,
его доступность, число МО, anchor и исходный расход.

C0 — сохранённый CatBoostDirect E02b, L0 — тот же legacy builder и 19
числовых K0 признаков, delta_y=y_target−last_available_y и прежний anchor.
CN/LN используют те же 19 формул на R: delta_R=R_target−last_available_R,
R_hat=anchor_R+predicted_delta_R; y_hat=max(0,N_hat×R_hat).
relative_delta_1 сохраняет delta_1/max(abs(lag_2),1); единица в знаменателе
для R относится к безразмерной шкале. Decomposition меняет признаки,
шкалу метки/ошибки learner и прогноз национального компонента вместе;
контраст не изолирует только качество N и не доказывает причинный эффект.
МО-ID не является признаком. Макро/тренд/one-hot/новости/погода/новый
календарь/дефлирование отключены; strict12 не добавляется.

### E05a: устойчивые решения и подтверждённые ограничения

География исходной панели: 2190 МО / 77 регионов; выборка E01: 64 МО / 37 регионов.
Явные territory_id/region_code/region_name используются без fuzzy matching;
many-to-one соединение не должно размножать или удалять строки.

Классы источников: A — подтверждённая историческая доступность конкретного
значения/версии; B — современная историческая таблица с неподтверждёнными
vintages; C — доступность или определение не установлены. Период значения,
дата публикации, дата конкретной версии и время загрузки — разные поля.
HTTP Last-Modified и наш download timestamp не доказывают дату публикации.
Сценарный лаг B допускается только отдельным сценарием и не превращает B в A.
Исторический пример r получает только макроданные/версии, доступные к r,
а не всю информацию, известную на позднюю дату обучения O. Для O действует
та же фильтрация доступности. Давность, происхождение и пропуски сохраняются.

### Формулы тренда E05a, реализованные в E05b
A — неизменный SeasonalNaiveYoY. Для B/C: C=O−L, D=h+L, последние шесть
календарных позиций t=C−5…C с конечными y_t,y_{t−12}, минимум три пары;
b=median((y_t−y_{t−12})/12) рублей/месяц. Сезонность отделяется годовой
разностью, а не регрессией по сырым сезонным месяцам. Полный конечный шаблон
последних 12 месяцев обязателен: a_m=y_{t_m}+b(C−t_m), l=mean(a_m), s_m=a_m−l.
B=max(0,l+s_{month(O+h)}+bD). C=max(0,l+s+b Σ_{j=1…D}0.9^j), phi=0.9 фиксировано.
При <3 парах или неполном шаблоне — явный неизменный SeasonalNaiveYoY с
причиной резерва. Декабрь 2023 не имеет годовых пар: B/C резервные на всех
горизонтах; все фактические h=12 случаи E01 — этот выпуск. Даты оценки не
расширяются для получения собственной годовой MAE тренда.
Без обучения проверена поддержка B/C: 1260/1890 конечных случаев E01,
по h=1/3/6/12 — 567/441/252/0; 630 потребуют резерва. Это доступность,
не результат прогнозирования и не доказательство улучшения.

## E02a: протокол прямых обучающих пар
Новый модуль src/sberforecast/direct_training.py не меняет supervised_training(),

Допуск МО для текущего прогноза E01: >=12 наблюдений, давность <=1 месяца.
Требования к каждому обучающему примеру задаются отдельно:
- legacy (A): непустой календарный префикс, конечные цель и anchor. Один
  известный факт достаточен; старый сборщик не ограничивает давность.
- strict12 (B): те же условия плюс >=12 конечных фактов на историческую дату.
- max_staleness_months — отдельный явный параметр обучающих примеров.
  В аудите он null для обоих режимов: strict12 меняет только число фактов.
  Это отличается от первой диагностической таблицы, где к strict12 также
  применялось ограничение давности <=1. Оно не переносится молча в E02a.

Для исторического выпуска r, горизонта h, лага L и текущего выпуска O:
feature_cutoff=r-L; target=r+h; target_available_at=конец месяца r+h+L <= O.
Индекс данных обозначает начало месяца, даты выпуска/доступности — конец месяца.
lag_k = y[(r-L)-(k-1) месяцев]; лаги привязаны к cutoff, не к месяцу цели.
Пропущенные календарные месяцы и неизвестные лаги остаются NaN. Только anchor
берётся через ffill из доступного префикса. mean/std/count и разности используют
тот же исторический префикс, что E01; календарные признаки описывают target.
Метка delta = y[target]-anchor, как в исходном CatBoost. В будущем восстановление
прогноза будет max(anchor + predicted_delta, 0); в E02a прогнозов нет.

Для h=1, L=0, max_staleness_months=null режим A точно совпадает со старым
сборщиком на месячной сетке по ключам, порядку строк, признакам и меткам.
При L>0 соответствие намеренно не точное: старый сборщик обучается следующему
месяцу после префикса, прямой сборщик — месяцу r+h с разрывом L+h от cutoff.
При отсутствии пар возвращаются пустые X/y/metadata; требования не ослабляются,
резервный прогноз не создаётся. Метаданные каждой строки содержат МО, дату r,
cutoff, цель, её доступность, O, число фактов, давность, anchor и значение цели.

## E04a: протокол онлайн-детекторов
Отдельные файлы online_detection.py, online_synthetic.py, online_evaluation.py,
online_experiment.py, online_report.py и scripts/run_online_detection.py.
Конфигурация configs/online_detection.yaml; результаты отдельно от E01–E03.
Основное событие — положительный/отрицательный сдвиг уровня расходов,
сохраняющийся минимум три месяца. Наклон и дисперсия — дополнительные
сценарии; одиночный выброс и неизменная сезонность — контроль без события.
Сигнал ошибки прогноза не доказывает экономический шок; будущее изменение
этим экспериментом не предсказывается.

Реальный вход выбран сейчас после просмотра E01: сохранённые h=1 прогнозы
SeasonalNaiveYoY, e=y_true−y_pred; новые модели расходов не обучаются.
Синтетика вызывает тот же неизменный baseline_predict по историческому
префиксу O−L, цель O+1 соответствует шагу L+1. Годовой коэффициент — медиана
отношений из трёх последних КАЛЕНДАРНЫХ позиций, с пропуском NaN внутри
этого окна, а не поиск трёх непустых отношений глубже; границы [0.5,2].
Центр c=median первых четырёх доступных e; фиксированный масштаб
s=max(1.4826 median|e−c|, 0.03 median|y_pred в warmup|, 1 рубль).
Мониторинг начинается со следующей доступной ошибки, z=(e−c)/s.
Пропуски не заполняются нулями, сохраняют календарь и не обновляют состояния.
Дата сигнала — конец observation_period+L; L=0 из E01 остаётся допущением,
публикации и vintages не подтверждены. Сброс после выданной тревоги;
два следующих полных календарных месяца подавляют выдачу, но не обновления.
Разрыв календаря не сбрасывает состояние. Старый detection.py не изменён:
там относительные ошибки, calibration по всей validation, pooled fallback,
только holdout-мониторинг, сброс после пропуска и cooldown по наблюдениям.

CUSUM двухсторонний; EWMA двухсторонний с дисперсией конечного старта,
выведенной из рекурсии для независимых z с единичной дисперсией. MAD и
четыре ошибки не гарантируют это предположение; частоты проверяются эмпирически.
BOCPD: точная рекурсия Adams–MacKay, Normal/NIG prior m=0,κ=1,a=2,b=1,
Student-t predictive, logsumexp, постоянный H из 1/24,1/60; без усечения.
P(r=0)=H постоянно в выбранной рекурсии; score=P(1≤r≤2) реагирует на данные.
Первые два обновления после reset не выдают сигнал из-за стартового артефакта.
Run length измеряется в доступных наблюдениях, не календарных месяцах.
Источники: [NIST CUSUM](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc323.htm),
[NIST EWMA](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc324.htm),
[Adams & MacKay](https://arxiv.org/abs/0710.3742).

Протокол до теста: 24 месяца, сезонность 10%, линейный тренд 0.4%/месяц,
Gaussian noise 1%/3%, силы 2/4/6 σ. По 30 повторов на ячейку: 1140 основных
и 120 граничных рядов в каждом наборе. Seeds validation 100000…101259,
test 200000…201259; ID не пересекаются. События main — май–сентябрь 2024.
Граничные мартовские события до мониторинга и ноябрьский кандидат сдвига
с двумя наблюдаемыми месяцами не включаются в основную оценку; последний
не подтверждает длительность ≥3 месяцев. Истина генератора не передаётся
прогнозу/масштабированию/детекторам. Все 18 кандидатов выбираются только
по validation: бюджет ≤1/12 observed monitoring months отдельно на no_change
и outlier; затем максимальная F1 level_up/down, recall, меньший max control
FAR, задержка и candidate_id. При отсутствии кандидата лимит не меняется.
Test создаётся после сохранения рабочих точек; реальные пороги не подбираются.
Окно события начало…+3 месяца включительно, сопоставление один-к-одному;
предшествующие и повторные сигналы — FP. Неполные окна сохраняются с явным
eligibility, сигналы внутри них отмечаются excluded_censored_event.
Precision/recall/F1, доля пропусков, задержка и FAR показываются отдельно
по сценариям/силе/шуму; неопределённость — 500 bootstrap целых рядов.
