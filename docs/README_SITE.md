# Интерактивный отчёт проекта

Сайт: [index.html](index.html). Можно открыть файл прямо в браузере:
локальные CSS, JavaScript, рисунок и встроенный data bundle работают без сервера,
CDN, установки пакетов и подключения к внешним источникам данных.

На странице представлены результаты исследования: прогнозирование,
обнаружение изменений, новости, ставка / USD-RUB и достаточность данных для
раннего предупреждения. Выбор горизонта и периода меняет отображение сохранённых
чисел; новые прогнозы и метрики не рассчитываются.

## Источники и обновление

Единственный источник определений — [terminology.md](../reports/final/terminology.md).
Генератор читает его и существующие публичные агрегаты из
`reports/final/` и `reports/results/e08b/`, `e08c/`, `e08d/`.
Списки входных файлов и их SHA256 сохранены в пяти JSON под `docs/data/`.
SHA текстовых источников вычисляется после приведения к LF и удаления UTF-8 BOM,
чтобы проверка работала при разных настройках Git line endings.
Рисунок `assets/figures/rolling_forecast.png` — побайтовая копия уже
опубликованного рисунка; новые муниципальные значения не выгружаются.

Из корня репозитория:

```powershell
python scripts/build_project_report.py
python scripts/build_project_report.py --check
git diff --check
```

Первая команда обновляет JSON, локальный JavaScript data bundle, статические
таблицы и словарь в HTML. Вторая проверяет, что они соответствуют текущим
сохранённым источникам. Скрипт использует стандартную библиотеку Python;
экспериментальные runners и модели не запускаются.

После изменения canonical словаря нужно повторить генерацию. HTML-определения
отдельно не редактируются. Первые пояснения терминов берутся из первого
предложения canonical определения; прямые ссылки открывают соответствующий
пункт полного словаря.

Таблицы и определения доступны без JavaScript. С JavaScript добавляются графики,
поиск по терминам и определениям, тематический фильтр, переключатели и тема.
У SVG и рисунка есть текстовое описание; значения доступны в таблицах.

## GitHub Pages

После review, commit и push автором:

1. Открыть repository **Settings → Pages**.
2. Выбрать **Deploy from a branch**.
3. Указать **main** и **/docs**, сохранить.

Ожидаемый адрес:
[MarselMiller.github.io/sberindex-municipal-forecasting](https://MarselMiller.github.io/sberindex-municipal-forecasting/).
Готовность файлов не означает, что сайт уже опубликован. Настройки GitHub
автоматически не изменялись.

Assets внутри `docs/` имеют относительные адреса, поэтому сама страница,
графики, таблицы и полный HTML-глоссарий работают и при размещении `docs/`
как корня отдельного статического сайта. Часть ссылок на методологию, PDF и
CSV ведёт в GitHub, часть — относительными путями в `../reports/`.
При приватном репозитории первые требуют доступа, а вторые отсутствуют
в публикации только `docs/`. Полный список — в
[аудите готовности](../reports/final/SUBMISSION_READINESS.md#доступность-материалов).

Минимальный следующий вариант: после отдельного согласования разместить
`docs/index.html`, `docs/assets/` и `docs/data/` как корень статического сайта.
Журналы `PROJECT_CONTEXT.md` и `TASKS.md` для работы страницы не нужны;
они содержат исторический контекст и не входят в этот пакет.
Основной отчёт не требует авторизации в GitHub.
Для открытых приложений можно отдельно согласовать копии выбранных PDF/Markdown/CSV
внутри site root и перенаправление ссылок. Сейчас ссылки сохранены, visibility
репозитория не менялась, публикация и создание новых репозиториев не выполнялись.

Перед публикацией проверить страницу на настольной и мобильной ширине,
переключатели, поиск, навигацию с клавиатуры и консоль браузера.
Состав новых данных ограничен итоговыми агрегатами, уже публичными национальными
признаками Банка России и копией существующего рисунка. Исторические ограничения
прав на исходные данные остаются в
[аудите публикации](../reports/final/DATA_PUBLICATION_AUDIT.md).
